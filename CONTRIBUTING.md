# Contributing

Thank you for improving this reference.

## Good contributions

- Correct a format capability with a primary specification or vendor source.
- Add a dependency-free browser example with accessible controls.
- Add benchmark results that follow `docs/benchmark-methodology.md`.
- Improve accessibility, error handling, or documentation clarity.
- Report a reproducible browser compatibility issue.

## Before opening a pull request

1. Keep the change focused.
2. Do not add copied text, copyrighted fixtures, tracking scripts, or unrelated product promotion.
3. Validate JSON and CSV files.
4. Test HTML examples in at least two current browser engines when possible.
5. Explain the motivation, test environment, and sources in the pull request.

## Data changes

For capability corrections, link to a specification, standards body, or browser vendor document. For benchmark data, include:

- source fixture license and checksum;
- operating system and browser version;
- input dimensions and byte size;
- output settings and byte size;
- measurement method;
- date measured.

## Conduct

Be accurate, constructive, and respectful. See `CODE_OF_CONDUCT.md`.
